# 网页版 SVG 编辑器

> **新增：零部件实物图 → 2D 线条图工具**（照片/线稿自动提取结构线条，输出纯矢量 SVG + PNG）
> 一键启动：双击 `启动线条图工具.bat`；完整说明见 **[README-线条图工具.md](README-线条图工具.md)**。
> 命令行：`python photo2line.py part.jpg out.svg --preset auto`
> 原有 SVG 编辑器与 `img2svg.py` 均未改动。

---


一个零依赖、纯前端的矢量图形编辑器。所有代码都是原生 HTML / CSS / JavaScript，
**无需安装任何环境、无需联网、无需打包构建**，双击 `index.html` 即可在浏览器中打开使用。

> 适合制作图标、示意图、简单插画、海报底稿，并导出为标准 SVG / PNG 文件。

---

## 快速开始

1. 直接双击 `index.html`（建议用 Chrome / Edge / Firefox 等现代浏览器）。
2. 左侧工具栏选择工具，在画布上绘制。
3. 右侧检查器调整属性；顶部工具条做对齐、层级、导入导出等操作。
4. 随时按 `Ctrl + Z` / `Ctrl + Shift + Z` 撤销 / 重做；编辑内容会自动保存到本地。

## 功能一览

### 绘制工具（左侧工具栏）
- **选择 / 平移**：选择并移动对象；平移画布（也支持空格拖拽或中键拖拽）。
- **矩形 / 椭圆**：按住拖拽绘制；`Shift` 锁定正方形 / 正圆；`Alt` 从中心向外绘制。
- **直线 / 箭头**：按住拖拽；`Shift` 锁定 15° 角；`Alt` 对称轴绘制。
- **折线 / 画笔**：单击添加节点，双击或回车结束；折线为折线，画笔为平滑曲线。
- **文本**：单击放置文本框，可编辑内容、字号、颜色。
- **图片**：导入本地 PNG / JPG 作为位图嵌入画布。

### 编辑操作
- 选中对象后出现包围框与控制点，**拖拽控制点缩放**，拖拽旋转手柄旋转。
- **组合 / 取消组合**（`Ctrl + G` / `Ctrl + Shift + G`）：把多个对象合并为一个整体，可整体移动、旋转、翻转、缩放。
- **对齐与分布**：顶栏「对齐」下拉，支持左 / 中 / 右、上 / 中 / 下对齐及等间距分布。
- **层级**：上移、下移、置于顶层、置于底层。
- **翻转**：水平 / 垂直翻转（也支持 `H` / `V` 快捷键）。
- **复制 / 粘贴**：`Ctrl + C` / `Ctrl + V`（同一页面内）。
- **删除**：`Delete` / `Backspace`。
- **锁定 / 隐藏**：在右侧图层面板中切换。

### 外观属性（右侧检查器）
- 填充、描边颜色与透明度，描边宽度、线帽、线型（实线 / 虚线）。
- 位置、尺寸、旋转角度、水平 / 垂直翻转。
- 文本字号、行高、对齐；图片可按比例缩放。

### 画布
- 自定义画布尺寸（像素）。
- 纯色背景或透明背景（透明时显示棋盘格）。
- 显示 / 隐藏网格、吸附网格（便于对齐）。

### 导入 / 导出
- **导出 SVG**：生成标准矢量文件，并把完整的可编辑模型嵌入到 `<metadata>` 中，
  之后用本编辑器再次打开即可继续编辑（所见即所得）。
- **导出 PNG**：按 2 倍分辨率栅格化导出。
- **打开 SVG**：导入 `.svg` 文件；若文件由本编辑器导出，将自动还原为可编辑对象；
  普通 SVG 也会尽力解析为可编辑图元。
- **源码查看 / 编辑**：顶栏「源码」可查看并手动修改 SVG 源码，点「应用」写回画布。

### 本地存储
- 编辑内容会自动保存到浏览器 `localStorage`，下次打开自动恢复。
- 「文件 → 清空」可新建空白画布；「文件 → 示例」载入内置示例。

## 图像转矢量工具 `img2svg.py`（图片 → 干净 SVG 线条）

把**黑白线条图（含数字热点）**转成真正的矢量 SVG：线条用 `<path>` 多边形笔触构成（不是位图套壳、不输出 `<image>`），热点数字用 `<text>` 标注（不用 `<circle>`）。

### 为什么"清晰 GIF 转 SVG 反而变糊"——以及本工具的取舍

原图 `1.gif` 是 2480×3508 的**二值图**：墨只占 5.9%，**56% 的墨像素半径≤1px，线宽中位数只有 2px**，
硬边、无抗锯齿。它"清晰"恰恰因为线极细且边界精确。

把这种图矢量化的根本困难：**1px 硬边是位图特性，矢量轮廓只能逼近、无法逐像素相等。**
SVG 轮廓沿像素中心走、渲染有抗锯齿，会向外渗约半像素；对 2px 线来说就是 25% 相对误差，
相邻细线一粘连就"糊"。之前采用的「骨架中心线 → 重建笔触」误差更大（±1px），
实测画到墨外的像素高达 **254358**（笔触比原墨膨胀 1.38 倍）——这才是糊的真正来源，
与原始分辨率无关。

因此 `--mode` 提供两种策略，默认 `exact`：

| 模式 | 做法 | 墨外像素（糊源） | 像素误差 XOR/墨 | 漏墨 |
| --- | --- | --- | --- | --- |
| `exact`（默认） | `findContours` 轮廓合并单 path + `fill-rule=evenodd` | **34096** | **0.281** | 21% |
| `centerline` | medial_axis 骨架 → 变宽笔触（+混合补漏） | 254358 | 0.732 | 8% |

`exact` 把糊源压到原来的 **1/7**，文件也最小（872KB）；代价是极细的 1px 孤立像素会漏掉约 21%
（这些是细线轮廓内部几乎无面积、fill 盖不到的部分）。`centerline` 覆盖更全但明显更糊。

> 实测中"每个轮廓单独 fill"会把孔洞填实（曾导致 218 万像素画到墨外），
> "单独加 1px stroke"又会向墨外渗半像素。二者都劣于**合并单 path + 纯 fill + evenodd**。
> `cv2.drawContours` 得到的 0.001 误差是像素栅格化假象，真实 SVG 渲染达不到。

### 转换流程（`exact` 模式）
1. **单色化**：`mono_mask` 二值化（阈值 245）。
2. **OCR 热点**：WinRT OCR（流读，绕过中文路径）识别 58 个数字；描线前擦除原数字，
   用 `<text>` 居中写回，外圈圆形标记保留为矢量线条。OCR 结果缓存到 `<输出>.ocr.json`。
3. **精确轮廓**：`cv2.findContours(RETR_CCOMP)` + `approxPolyDP(0.5px)`，
   合并为**单个 `<path>`**（纯 `M/L/Z`）+ `fill-rule="evenodd"` 挖空孔洞。
4. **分层输出**：白色 `<rect>` + `<g id="strokes">` + `<g id="hotspots">`。
   无 `<image>`、无 `<circle>`、无 `data:`/base64 位图。

### 安装依赖
```powershell
pip install numpy opencv-python scipy scikit-image pillow pymupdf
# WinRT OCR 仅 Windows 自带，无需 pip（需系统已装英文 OCR 语言包）
```

### 用法
```powershell
# 默认（--mode exact）：像素级忠实轮廓，最清晰，自动 OCR 并缓存
python img2svg.py 1.gif 1.svg

# 轮廓简化程度：越小越忠实、文件越大（默认 0.5px）
python img2svg.py 1.gif 1.svg --contour-simplify 0.0

# 切回骨架中心线方案（覆盖更全但更糊）+ 混合补漏
python img2svg.py 1.gif 1.svg --mode centerline
python img2svg.py 1.gif 1.svg --mode centerline --no-hybrid

# 低分辨率快速预览（只降采样，安全不卡机）
python img2svg.py 1.gif preview.svg --scale 0.4

# OCR 控制
python img2svg.py 1.gif 1.svg --no-ocr       # 跳过 OCR（有缓存仍复用）
python img2svg.py 1.gif 1.svg --force-ocr    # 强制重新识别
```

### 常用参数
| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--mode` | `exact` | `exact`=精确轮廓（最清晰）/ `centerline`=骨架中心线笔触 |
| `--contour-simplify` | `0.5` | `exact` 模式轮廓简化阈值(px)，越小越忠实、文件越大 |
| `--scale` | `1.0` | 降采样比例，用于快速预览（如 `0.4`） |
| `--var-width` / `--no-var-width` | 开 | 仅 `centerline`：变宽钢笔笔触 vs 固定线宽 |
| `--vfactor` | `1.0` | 变宽半宽 = 该值 × 本地距离变换半径（<1 更细、>1 更粗） |
| `--wfactor` / `--wpct` / `--wcap` | `1.7` / `30` / `12` | 仅 `--no-var-width` 时生效：固定线宽 = `wfactor × 半径分位数`，上限 `wcap` |
| `--erase-margin` | `3` | 擦除原数字 bbox 的外扩像素（保留外圈圆形标记） |
| `--no-hybrid` / `--min-block` | 开 / `24` | 关闭混合补漏 / 补漏最小连通域像素数 |
| `--no-ocr` / `--force-ocr` | — | 跳过 / 强制重新 OCR |
| `--lang` | `en-US` | OCR 语言 |
| `--stroke` | `#1f2329` | 线条颜色 |
| `--font-size-ratio` | `0.95` | 热点数字相对原数字框的字号比例 |
| `--close` / `--max-gap` / `--prune` | `2` / `3` / `6` | 仅 `centerline`：骨架闭运算核 / 断笔桥接 / 短枝裁剪 |

### 性能提示
- `exact`（默认）只做 `findContours`，全分辨率也很快（秒级）。
- `centerline` 的全分辨率 `medial_axis` 较重，**每个 SVG 只需完整跑一次**；
  迭代调参时用 `--scale 0.4` 预览，确认后再跑一次全分辨率。
- OCR 结果会缓存到 `<输出>.ocr.json`，再次运行（不指定 `--force-ocr`）直接复用，
  不会重复调用 OCR。
